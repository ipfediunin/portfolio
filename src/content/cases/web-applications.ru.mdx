## Проблема

Заказчику нужен не отдельный API и не набор страниц, а работающий продукт: интерфейс, через который пользователи выполняют действия, серверная логика, которая их обрабатывает, и данные, которые надёжно сохраняются. Все части должны быть согласованы между собой.

## Моё участие

- Проектировал структуру приложений.
- Разрабатывал frontend на React и Next.js.
- Разрабатывал серверную логику и API на Python — на Django, FastAPI или Flask в зависимости от проекта.
- Интегрировал приложения с базами данных.
- Реализовывал пользовательские формы и валидацию данных.
- Делал адаптивные интерфейсы и оптимизировал взаимодействие клиента и сервера.

## Техническая архитектура

UI → запрос → backend → бизнес-логика → база данных → ответ → UI. Интерфейс отвечает за удобство и мгновенную обратную связь, backend — за проверку данных и правила, база данных — за сохранность.

## Особенности реализации

- **Валидация с двух сторон.** Браузер проверяет ввод сразу, чтобы не отправлять заведомо ошибочный запрос; сервер проверяет снова, потому что запрос можно отправить и в обход формы.
- **Сервер — источник правды.** Состояние в интерфейсе может устареть. Конфликты, например уже занятое время, определяет сервер и возвращает понятный ответ.
- **Транзакции.** Связанные изменения данных выполняются вместе или не выполняются вовсе.
- **Адаптивность.** Интерфейсы рассчитаны на разные размеры экранов.

## Результат

Законченные веб-приложения, в которых интерфейс, серверная логика и данные работают как одно целое: пользователь выполняет действие, система проверяет его, применяет правила и сохраняет результат.
