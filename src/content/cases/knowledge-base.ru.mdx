## Проблема

Знания организации распределены по документам: регламентам, инструкциям, описаниям процессов. Поиск по ключевым словам справляется с этим плохо: вопрос и документ сформулированы разными словами, а найденный файл всё равно приходится дочитывать самому. Нужна система, которой можно задать вопрос на естественном языке и получить ответ, основанный на собственных источниках организации, а не на общих знаниях языковой модели.

## Моё участие

- Спроектировал RAG-пайплайн: подготовку и индексацию документов, поиск контекста и формирование ответа.
- Разработал backend API на FastAPI для вопросов и работы с индексом.
- Реализовал разбиение документов на смысловые фрагменты и хранение фрагментов вместе с метаданными.
- Реализовал механизм поиска по векторным представлениям документов на pgvector и Milvus.
- Интегрировал языковую модель и организовал передачу ей найденного контекста.
- Подключил Redis для кэширования, чтобы повторяющиеся операции не выполнялись заново.

## Техническая архитектура

- **Индексация.** Документы проходят очистку и разбиваются на фрагменты, для фрагментов считаются эмбеддинги, векторы сохраняются вместе с метаданными.
- **Ответ на вопрос.** API проверяет кэш, переводит вопрос в вектор, ищет ближайшие фрагменты и передаёт их языковой модели как контекст.
- **Векторные хранилища.** pgvector держит векторы рядом с реляционными данными в PostgreSQL, поэтому поиск сочетается с обычными SQL-фильтрами. Milvus — отдельная векторная база с индексами для приближённого поиска по большим коллекциям.

## Особенности реализации

- **Фрагменты.** Размер фрагмента — компромисс: крупный размывает смысл вектора, мелкий теряет контекст. Перекрытие соседних фрагментов сохраняет мысль, которую разорвала граница.
- **Релевантность.** В контекст передаются только наиболее близкие фрагменты. Низкое сходство — сигнал, что ответа в базе нет, и модель не должна его додумывать.
- **Контекст запроса.** Число фрагментов ограничено: ответ остаётся точным, а запрос укладывается в контекст модели.
- **Метаданные.** Фрагмент хранит ссылку на исходный документ, поэтому ответ можно проверить по источнику.

## Результат

Система позволяет задавать вопросы по внутренним документам на естественном языке и получать ответы, опирающиеся на найденные фрагменты, со ссылками на источники. Чтобы добавить новые знания, документы достаточно проиндексировать — дообучать модель не нужно.
