## Проблема

Многие рабочие действия удобнее выполнять в мессенджере, чем в отдельном приложении: узнать статус, отправить отчёт, задать вопрос. Для этого нужен бот, который понимает команды, ведёт пользователя по многошаговым сценариям, обращается к внешним сервисам и сохраняет результат.

## Моё участие

- Проектировал логику ботов и обработку пользовательских команд.
- Разрабатывал backend-обработчики на Flask.
- Интегрировал сторонние API.
- Создавал автоматизированные сценарии и работал с данными.
- Хранил состояние диалогов и результаты в Redis и PostgreSQL.
- Добавлял AI-функциональность через LLM API.

## Техническая архитектура

Пользователь → платформа мессенджера → webhook на Flask → обработчик команды → внешний API, LLM или база данных → ответ пользователю. Состояние диалога хранится отдельно от обработчика, в Redis, поэтому каждое сообщение обрабатывается с учётом предыдущих шагов.

## Особенности реализации

- **Команды и сценарии.** Простые команды отвечают сразу, а многошаговые сценарии устроены как конечный автомат: на каждом шаге бот знает, чего ждёт от пользователя.
- **Внешние API.** Недоступность внешнего сервиса — не повод молчать: пользователь получает понятный ответ.
- **LLM для свободного текста.** Вопросы вне команд передаются языковой модели.
- **Данные.** Результаты сценариев сохраняются в базе, а не только в переписке.

## Результат

Боты выполняют задачи пользователей прямо в мессенджере: отвечают на команды, ведут через многошаговые сценарии, получают данные из внешних систем и сохраняют результаты.
