PixiJS-чанк грузится только на страницах со сценой. Демо кейсов — отдельные клиентские компоненты: в браузер уходит только демо открытого кейса; мир кейса строится при входе и уничтожается при уходе.

### Аудит механизмов (по коду, без изменений в этом этапе)

- Code splitting / lazy: `SceneViewport` → `dynamic(..., { ssr: false })`, движок не загружается без слота.
- Текстуры: статичная графика запекается (`TextureBaker`) под текущий зум, спрайты не растягиваются; неподвижные слои — отдельные render group.
- DPR ограничен; тиры качества; пауза по `visibilitychange`.
- Reduced motion: сцена — неподвижный кадр (e2e).
- Без WebGL — SVG-постер, playground работает на DOM-панелях (e2e).
- Утечки: мир кейса уничтожается при уходе; e2e проверяет, что canvas один на всё приложение.

## Нерешённые вопросы

- Базовые ≈ 195 КБ JS на текстовых страницах (Next runtime, React, оболочка) — приемлемо, но можно проверить, что root layout не тянет лишнего (`StageProvider` и zustand). Не блокирует запуск.
- Замер на реальном среднем Android и Lighthouse/PageSpeed Insights на production-URL — **EXTERNAL**: нужен публичный адрес и устройство.
