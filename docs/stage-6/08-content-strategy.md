# 08 · Контент, позиционирование и внешние каналы

## Позиционирование

- H1 главной: **Full-Stack & AI Engineer** (как в ТЗ).
- Подзаголовок из ТЗ — «I build intelligent applications, reliable backend systems, and automation solutions». Заменён на: _«I build reliable Python backends, RAG and LLM features and business automation — together with the React and Next.js interfaces people use them through.»_ Почему: исходная фраза не называет ни Python, ни RAG/LLM — то, что совпадает с вакансиями (Python backend + AI/RAG) и запросами услуг; «intelligent applications» — расплывчато. Новая фраза отвечает на «кто, на чём, что делает» в одном предложении.
- Eyebrow: «Python backend · RAG & LLM · Automation». Факты под hero: Python backend / AI systems / Full-stack / Open to work.
- Title главной: «Full-Stack & AI Engineer — Python Backend, RAG and Automation».

## Правила текста

- Английский без рекламных штампов (нет «cutting-edge», «world-class», «seamless», «guaranteed»); короткие активные предложения.
- Только подтверждённое: стек — из `about.profile`; ни лет опыта, ни компаний, ни сертификатов, ни уровней; DRF, WebSocket, Celery, CI/CD, JWT не заявляются.
- Не создаётся впечатление, что все технологии были в одном проекте: услуги перечисляют технологии направления, кейсы — только свои.
- Нет сроков, цен и гарантий (проверяет юнит-тест).

## Кейсы

- Структура истории: **Problem → Solution → My role → Technical architecture → Implementation → Functional outcome**; стек — в боковой колонке; интерактивная модель — над историей. Раздел Solution пересказывает уже подтверждённую архитектуру, новых фактов не добавляет.
- **Основа кейса** (`basis`, метка под описанием):
  - `project` — «Project work», одна конкретная система: 01 Knowledge Base, 04 Corporate Messenger;
  - `practice` — «Generalised experience across several systems»: 02, 03, 05, 06, 07, 08;
  - `site` — «This website»: 09.
    Распределение консервативное: где формулировки истории во множественном числе («built automation services», «the bots») или есть `note`, выбран `practice`. Метки подтверждены владельцем 2026-11-04.
- Демо подписано как модель на синтетических данных; метрики показываются только измеренные (есть только у 09 — замеры сцены).
- Имена 9 кейсов и их порядок не менялись.

## Предположения

- Метка основы снижает риск недоверия к кейсам без названий клиентов: читатель видит, что это обобщение опыта, а не скрытый «крупный клиент».
